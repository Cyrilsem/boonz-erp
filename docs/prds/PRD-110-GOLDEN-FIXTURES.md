# PRD-110 GOLDEN FIXTURES — the proof harness (build FIRST)

Law: no engine change lands before the fixture that proves it; no incident closes without its fixture. Harness = `golden` schema: `golden.fixtures(id, name, source_incident, phase_required)`, `golden.snapshots(fixture_id, table_name, rows jsonb)` (frozen input state), `golden.assertions(fixture_id, seq, description, check_sql, expect)`. Runner: `golden.run_fixture(id)` → loads snapshot into an isolated plan_date/namespace, executes the scenario RPCs, evaluates assertions, returns pass/fail + diff. `golden.run_all()` nightly + before every phase gate. Failures HALT the loop (goal command rule 8).

Snapshot recipe: capture real rows (machines, shelf_configurations, slot_lifecycle, WEIMI snapshot, warehouse_inventory, product_mapping/product_sourcing subset) for the named machines on the named date into golden.snapshots. Fixtures run on synthetic plan_dates (year 2030) to never collide with live.

> ⚠️ **Fixture 24 — premise restated twice, spec text above left as originally written.** Retirement is
> **not** a `DELETE`: 255 `inventory_audit_log` rows reference the 40 sentinels under a NO ACTION FK, so
> it aborts (leg 10). It is **not** `inactivate_warehouse_row` either: that writer refuses any row with
> `warehouse_stock > 0`, and after a drain the trigger `tg_propose_inactivate_on_zero_stock` has already
> flipped the row to `Inactive`, so the writer refuses a second time (leg 11). Canonical retirement is
> **one** `apply_inventory_correction(id, NULL, NULL, NULL, 0, reason, cs)` per row. The fixture as built
> exercises that path on all 40 real rows inside a rolled-back subtransaction: 34 assertions, green.
> The SOA clause of the original spec is preserved and proven (101,181.71, delta 0). See D-09 / S-16.
